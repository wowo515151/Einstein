API Reference

Import public names from src/relativity/index.js. The examples show executable imports and common operations. These tables guide users to principal methods; follow the topic pages for shapes, conventions, options, numerical limits, and differences from Lib4.

Coordinates use [ct,x,y,z] and the default Minkowski metric has signature (-,+,+,+). Values use plain JavaScript numeric arrays. Many operations support compatible leading batch dimensions, but this is not a general PyTorch replacement; see each topic before relying on broadcasting. Invalid dimensions, non-finite values, singular matrices, superluminal velocities, and invalid causal normalization can throw.

Algebra

See Algebra for component layouts, batching, and metric conventions.

TypeConstruction and operations
Vector4Construct from four components or a batch. add, subtract, scale, dot, and normSquared perform arithmetic; causalType and causalName classify; normalizeTimelike and normalizeSpacelike require the corresponding causal type. outer, wedge, transform, lowerIndex, and toArray provide tensor and conversion operations.
Covector4add, scale, and pair operate on covectors; raiseIndex uses a metric and transform applies a transformation.
Matrix4identity constructs an identity matrix. add, multiply, apply, transpose, determinant, and inverse provide matrix operations.
Tensor4outer, contract, permuteIndices, raiseIndex, lowerIndex, symmetrize, antisymmetrize, and transform operate on tensors.
Bivector4wedge constructs a bivector from vectors. dual, contract, transform, and invariants operate on it. Invariant values retain the batch shape inside the returned object.
Metric4minkowski constructs the flat metric. dot, intervalSquared, lowerIndex, raiseIndex, determinant, and inverseMetric expose metric operations; g and inverseComponents expose components.
LeviCivita4symbol, epsilon, volumeForm, and dual supply permutation and volume-form operations.
LorentzTransformidentity, boost, fromRapidity, and rotation construct transformations. validate, compose, inverse, applyVector, and applyTensor check and apply them.
PoincareTransformidentity, compose, and inverse handle affine transformations; applyEvent applies translation and applyVector applies the linear part.

Mechanics and fields

See Physics and fields for units, grid layouts, result shapes, and numerical limitations.

TypeConstruction and operations
FourVelocityfromVelocity3(v,c) constructs a value from a subluminal three-velocity. gamma(), toVelocity3(), relativeVelocity(other), and validate() inspect it.
FourMomentumfromMassVelocity(m,v,c) constructs momentum. energy(), momentum3(), invariantMass(), and boost compute derived values.
FourCurrentfromChargeCurrent(rho,j,{c}) constructs a current. chargeDensity(), spatialCurrent(), and transform inspect or transform it.
EMFieldTensorfromEB(E,B,{c,epsilon0}) constructs a field. electricField, magneticField, dual, transform, lorentzForce, and energyMomentumTensor operate on it. invariants() returns named values magneticMinusElectricOverC2 and electricDotMagnetic.
MaxwellEquationsevolve(E,B,{spacing,dt,steps,current}) returns [electricTimes,electricHistory,magneticTimes,magneticHistory]. maxwellResiduals, constraintResiduals, and energyMomentumTensor provide checks and derived quantities.
RetardedFieldConstruct from position and velocity functions, charge, a speed bound, and options. retardedTime finds the source time; retardedPotential, evaluate, and sample return four-potential values.

Curved geometry

See Differential geometry for metric callbacks, finite-difference steps, index conventions, and integration limits. Numerical convergence must be checked for the application.

TypeOperations
DifferentialOperators4partial, jacobian, gradient, divergence, exteriorDerivative, hodgeDual, and dAlembertian evaluate field derivatives and related operators. partialForward, jacobianForward, and gradientForward offer explicit first-order dual-number differentiation.
Connection4christoffel, covariantDerivativeVector, covariantDerivative, parallelTransport, and geodesicAcceleration use the metric connection; christoffelForward accepts an explicitly dual-compatible metric, and {metricDerivative:"forward"} selects it for connection workflows.
Curvature4riemann, ricci, ricciScalar, einsteinTensor, and kretschmannScalar compute curvature quantities.
Geodesic4integrate produces samples along an initial-value geodesic; solveBoundary shoots for an endpoint. The components format returns separate parameter, event, and tangent histories.

Context and acceleration

RelativityContext groups a metric, units, c, and epsilon0 with factories for the common algebra, spacetime, and physics values. Its setUnits and toDevice return configured contexts; they do not convert existing values or transfer JavaScript arrays to a device. See Physics and fields.

minkowskiDotBatch offers an asynchronous CPU or optional WebGPU path for flat batches of four-vectors. spacetimeIntervalSquaredBatch applies the same backend to displacements between paired event batches. lorentzTransformBatch applies one validated Lorentz matrix to a flat vector batch through four screened dot batches. WebGPUBackend exposes supported, initialize, minkowskiDotBatch, and dispose for explicit backend reuse. See GPU and CPU backends for fallback behavior, precision, and ownership.

samplePlaneWaveBatch samples normalized electric and magnetic plane-wave fields at flat batches of four-coordinate events, using the CPU or the optional WebGPU backend. Its wave model, supported GPU envelope, return values, and fallback behavior are described in GPU and CPU backends.

samplePlaneWaveGrid builds a bounded rectangular spatial grid and samples the same model at one coordinate time, returning flat events and fields with z varying fastest. See GPU and CPU backends for its options and limits.
