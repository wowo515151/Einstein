# Physics and Fields

## Mechanics values

| Call | Returns |
| --- | --- |
| `new FourVelocity(components,{c})`, `FourVelocity.fromVelocity3(v,c)` | A `FourVelocity` from four-components or a subluminal three-velocity. The speed of light is optional and defaults to SI. |
| `u.gamma()`, `u.toVelocity3()` | A scalar gamma or three-velocity array, preserving leading batches. |
| `u.relativeVelocity(other)` | The other velocity's three-components in this observer's instantaneous rest frame; both values must use the same `c`. |
| `u.validate({atol,rtol})` | One Boolean indicating whether all samples are future-directed and normalized. |
| `new FourMomentum(components,{c})`, `FourMomentum.fromMassVelocity(m,v,c)` | A `FourMomentum` storing `(E/c,p)`; mass and velocity batches may broadcast. |
| `p.energy()`, `p.momentum3()`, `p.invariantMass({clampRoundoff})` | Energy, three-momentum components, or invariant mass, with leading batches preserved. |
| `p.boost(transform)` | A new `FourMomentum` under a validated Lorentz transform or matrix. |
| `new FourCurrent(components,{c})`, `FourCurrent.fromChargeCurrent(rho,j,{c})` | A `FourCurrent` storing `(cρ,j)`. |
| `current.chargeDensity()`, `current.spatialCurrent()`, `current.transform(matrix)` | Charge density, spatial current, or a transformed `FourCurrent`. |

Maxwell residual time differences divide directly by the timestep, including at subnormal timesteps. Both spatial and residual time differences divide terms separately if finite samples have an overflowing difference, and reject an unrepresentable derivative. These measures do not guarantee accuracy for arbitrary extreme-scale histories.

`FourVelocity.fromVelocity3(v,c)` rejects `|v|≥c`, constructs a normalized future-directed four-velocity, and exposes `gamma`, `toVelocity3`, and `validate`. `relativeVelocity(other)` returns the three-velocity of `other` after transforming it into this observer's instantaneous rest frame; compatible batch shapes broadcast. Construction preserves Lib4's distinction between shape validity and physical validation, so use `validate()` when accepting externally supplied four-velocities. Mechanics tensors are bounded to one million components and rank eight. `FourMomentum.fromMassVelocity(m,v,c)` stores `(E/c,p)` and broadcasts compatible mass/velocity batch dimensions. `energy`, `momentum3`, and `invariantMass` preserve batches; `boost` accepts a single or broadcast batch of Lorentz matrices and validates each applied matrix. Invariant-mass roundoff tolerance scales with momentum magnitude. With `clampRoundoff:false`, JavaScript still throws for a small negative residual within tolerance to avoid returning `NaN`; Lib4's direct square root can return `NaN` for that opt-out case. `FourCurrent.fromChargeCurrent(rho,j,{c})` stores `(cρ,j)` and broadcasts compatible leading dimensions of `rho` and `j`; `chargeDensity` and `spatialCurrent` preserve those dimensions. `transform` broadcasts a single or batched Lorentz matrix over the current batch and validates every applied matrix. The local Lib4 FourCurrent API has no separate field-coupling method. `MaxwellEquations` accepts a `FourCurrent` value as its grid source when its batch and spatial shapes match the field grid.

Lib4 frozen dataclass value objects freeze their JavaScript instance fields after construction: `Event4`, `SpacetimeInterval`, `LightCone`, `SpatialSlice`, `InertialFrame`, Lorentz/Poincare transforms, mechanics values, and `MaxwellEquations`. This matches dataclass field reassignment behavior; nested component arrays remain ordinary mutable JavaScript arrays, as Lib4's contained tensor data is mutable too.

`RelativityContext` keeps `c`, units, `epsilon0`, and a metric together. Natural units require `c=1` and default to `epsilon0=1/(4π)`. Factories for vectors, covectors, tensors, events, intervals, frames, light cones, spatial slices, four-velocity, four-momentum, four-current, electromagnetic fields, Maxwell equations, and retarded fields are available. Factories that depend on `c` or `epsilon0` propagate those context constants; representative algebra and mechanics factories are tested directly. `setUnits` returns a context with new constants but does not convert existing values. `toDevice` returns a context carrying the requested device label; plain JavaScript arrays do not move to a device, and WebGPU work remains explicit through `WebGPUBackend`. Lib4's PyTorch dtype/device placement and tensor-transfer semantics are not implemented.

When a `Metric4` instance is supplied, the context creates a validated metric wrapper while retaining the component arrays. Contexts returned by `setUnits` and `toDevice` also have distinct wrappers over those arrays. Mutating shared components affects each context, but replacing one wrapper's `g` does not replace the others. Construct a separate `Metric4` from copied components when independent storage is required. Validation performed when a metric is constructed does not prevent later mutation. `setUnits` uses the unit system's default speed of light when its `c` option is omitted or `null`.

`EMFieldTensor.fromEB(E,B,{c,epsilon0})` combines the electric and magnetic fields into an antisymmetric tensor and broadcasts compatible field batch dimensions. Field accessors, invariants, dual, Lorentz transformation, Lorentz force, and stress-energy preserve batches; tensor and transform dimensions broadcast where applicable. `invariants()` returns named `magneticMinusElectricOverC2` and `electricDotMagnetic` values, each with the field batch shape; Lib4 returns the same two values as a tuple. Batched JavaScript results previously used an array of objects. The magnetic-minus-electric scalar uses an exact-product fallback when individual products overflow or underflow, preserving selected representable residuals; ordinary floating-point cancellation can still lose precision. The pseudoscalar uses scaled arithmetic when intermediate electric components or products overflow or underflow; extreme cancellation and scale disparities can still lose precision. Applied Lorentz matrices are validated, and inputs are bounded to one million scalar components and rank eight.

`FourVelocity.u` and `FourMomentum.p` expose the same component arrays as their respective `components` properties, corresponding to the Lib4 field names. The objects are shallow-frozen: these properties cannot be reassigned, but their nested arrays remain mutable.

## Electromagnetic tensor

| Call | Returns |
| --- | --- |
| `new EMFieldTensor(components,{c,epsilon0,validate})` | An electromagnetic tensor from antisymmetric 4×4 components; validation is enabled by default. |
| `EMFieldTensor.fromEB(E,B,{c,epsilon0})` | An electromagnetic tensor constructed from electric and magnetic three-vectors. |
| `field.electricField(c)`, `field.magneticField()` | Electric or magnetic component arrays; omit `c` or pass `null` to use the field's configured value, or supply a positive override. |
| `field.invariants(c)` | `{magneticMinusElectricOverC2,electricDotMagnetic}`, each a number or batch. Omit `c` or pass `null` to use the field's configured value. |
| `field.dual({orientation})`, `field.transform(matrix)` | A new `EMFieldTensor`; orientation defaults to `1`. |
| `field.lorentzForce(charge,uCovariant)` | Four-force component arrays. Supply covariant four-velocity components or a `Covector4`, and consistent units; a contravariant `Vector4` must first be lowered with a metric. |
| `field.energyMomentumTensor(metric,{epsilon0})` | 4×4 stress-energy component arrays; metric and permittivity override are optional. |

`MaxwellEquations.evolve(E,B,{spacing,dt,steps,current})` uses periodic forward/backward Yee-style differences with electric samples at whole times and magnetic samples at half times. It returns `[electricTimes,electricHistory,magneticTimes,magneticHistory]`. Up to seven leading batch axes are preserved after the history time axis; electric, magnetic, and supplied current grids must have matching batch and spatial shapes. A current may be supplied as a spatial-current grid `[...,Nx,Ny,Nz,3]` or four-current grid `[...,Nx,Ny,Nz,4]` in `(cρ,j)` order, or as a compatible batched `FourCurrent`. `maxwellResiduals` returns discrete Ampère and Faraday history residuals; `constraintResiduals` returns Gauss electric and magnetic residuals with discrete charge continuity. `maxwellResiduals` also accepts the zero-step boundary case of one electric frame and an empty magnetic history (`[]`), returning empty Ampère and Faraday histories; JavaScript infers the missing trailing grid axes from the electric frame. `constraintResiduals` still requires at least one magnetic half-step frame. Each grid is limited to 32,768 cells and total stored history to 1,000,000 scalar field components across all batches and times. Residual and constraint APIs preflight the combined history shape against this limit before traversing and copying frame data. Nested grid/history arrays must be acyclic and use no more than twelve dimensions. The 3D Yee CFL condition is checked. When c squared overflows, underflows, or becomes subnormal, electric updates and Ampère residuals use scaled products. Current coupling avoids explicitly forming an unrepresentable inverse permittivity; the electric Gauss residual also rescales charge continuity when permittivity is subnormal. This does not guarantee accuracy for all extreme grid values. The implementation does not reproduce PyTorch device/autograd behavior or component-specific Yee offsets. `RetardedField.retardedTime(event)` and `retardedPotential(event)` accept event arrays shaped `(...,4)` and preserve their leading dimensions; `evaluate` and `sample` use the same batched potential contract. Root finding checks the lower endpoint of a distance-based bracket before bounded bisection and rejects a clear bracket failure, which may indicate an invalid speed bound. This endpoint check does not prove the bound along the whole trajectory. Aggregate batch root-work is capped at one million trajectory evaluations. If floating-point time spacing prevents further bracket refinement before the requested tolerance is reached, it returns an exactly represented root when found and otherwise rejects. Source speed is checked against both `c` and its declared bound. Point-charge potential is singular on the source worldline; separations indistinguishable from zero at the coordinates' floating-point scale also reject. Small nonzero separations near the origin are not rejected solely because they are small in absolute units. Non-finite observation times, root brackets or residuals, and potential components are rejected; representable results at extreme scales are not generally guaranteed. PyTorch device/dtype/autograd behavior is not represented.

## Maxwell solver and retarded potential

| Call | Returns |
| --- | --- |
| `new MaxwellEquations({c,epsilon0})` | A solver with optional physical constants. |
| `solver.evolve(E,B,{spacing,dt,steps,current})` | `[electricTimes,electricHistory,magneticTimes,magneticHistory]`; `dt` is required, while spacing and steps have defaults. |
| `solver.evolveDirectional(E,B,dE,dB,{spacing,dt,steps,current,currentDirection})` | `{values,direction}`: the ordinary evolution and one directional field sensitivity, each using the same four-entry history format. |
| `solver.maxwellResiduals(electric,magnetic,{spacing,dt,current})` | `{ampere,faraday}` discrete residual histories; use the same spacing, timestep, and current as the evolution. |
| `solver.constraintResiduals(electric,magnetic,{spacing,dt,current})` | `{gauss_e,gauss_b}` constraint histories, including charge continuity from the supplied current. |
| `solver.energyMomentumTensor(field,metric)` | Stress-energy component arrays; field and solver constants must match. |
| `new RetardedField(positionAtTime,velocityAtTime,charge,maxSpeed,{c,epsilon0,maxIterations,tolerance})` | A point-charge potential model. Callbacks accept scalar time and return spatial triples. Only the listed option names are accepted; unknown or misspelled names throw. `maxIterations` defaults to `96` and must be an integer from `1` to `4096`; `tolerance` defaults to `1e-12` and must be positive and finite. |
| `field.retardedTime(event)` | Retarded time as a number or batch for event coordinates shaped `(...,4)`. |
| `field.retardedPotential(event)`, `field.evaluate(event)`, `field.sample(events)` | Contravariant four-potential components `(φ/c,A)` with leading event batches preserved. |

For physically meaningful stress-energy calculations, supply a symmetric, nonsingular covariant metric. Raw matrices are accepted for compatibility with Lib4; lowering both field indices uses the full `G F Gᵀ` contraction even if a raw matrix is not symmetric. Nonsymmetric matrices are not physical metrics in this model.

`evolveDirectional` propagates a direction in the initial electric field, magnetic field, and optional static current at fixed `c`, `epsilon0`, spacing, timestep, and step count. Its four field inputs must have matching grid and batch shapes; `currentDirection` follows the same shape and `FourCurrent` rules as `current`, and defaults to zero. Each result's first and third entries are the ordinary sample times, not derivatives of time. The field histories in `direction` are directional derivatives of the linear discrete update in exact arithmetic; floating-point rounding and extreme-scale fallbacks can affect agreement. The two evolutions each use the ordinary history limits, and returned histories can occupy twice the memory of one call. This is not general PyTorch autograd and does not differentiate solver controls or the current's charge-density component.

For constraint sensitivities at fixed controls, pass the directional electric and magnetic histories to `constraintResiduals` using the same spacing and timestep and pass `currentDirection` as its `current`. Because the discrete constraints are linear in those inputs, the resulting residuals give their directional changes in exact arithmetic, including the initial charge-density direction. The usual numerical limits still apply.

## Shared context

`new RelativityContext({metric,c,units,epsilon0,device})` groups constants and factories. Use `createVector`, `createCovector`, `createTensor`, `createEvent`, and `createSpacetimeInterval` with their component inputs. Use `createInertialFrame(origin,{orientation,relativeVelocity})`, `createLightCone(apex,{branch,atol})`, and `createSpatialSlice(origin,normal,basis,options)` for spacetime objects. Mechanics factories include `createFourVelocity(components)`, `fourVelocityFromVelocity3(v)`, `createFourMomentum(components)`, `fourMomentumFromMassVelocity(m,v)`, `createFourCurrent(rho,j)`, `createEMFieldTensor(E,B)`, `createMaxwellEquations()`, and `createRetardedField(position,velocity,charge,maxSpeed,options)`. Context-dependent constants are supplied by the context. The retarded-field factory accepts `maxIterations` and `tolerance`; do not pass `c` or `epsilon0`, which are fixed by the context, or unrecognized option names. `context.setUnits(units,options)` and `context.toDevice(label)` each return a new context without converting existing arrays or values.

Electric-field extraction and Lorentz force reject non-finite outputs. Lorentz force uses scaled four-term products to retain representable results when naive intermediate multiplication overflows. Batched regression checks that four-force is orthogonal to four-velocity. Metric4 inputs to stress-energy calculations must retain their constructed batch shape.

The electromagnetic dual accepts tensors admitted by the electromagnetic constructor’s relative antisymmetry tolerance; the antisymmetric contraction determines the result.

Four-current charge-density and spatial-current extraction validate the current component arrays; charge density rejects an unrepresentable non-finite result.

Four-momentum and four-velocity accessors validate mutable component arrays; energy and gamma reject non-finite outputs.

Invariant mass normalizes momentum before division when individual component-to-c ratios overflow and retries in scaled units when the unscaled squared norm underflows. These paths preserve selected representable results; near-null cancellation and other extreme scales can still lose precision.

`FourVelocity.validate({atol,rtol})` uses an absolute plus relative mass-shell tolerance. At very small `c`, a large absolute tolerance relative to `c²` can admit a null or otherwise off-shell vector; choose tolerances appropriate to the units and scale. If `c²` underflows to zero and normalizing components overflows, representable absolute comparisons are retained when the absolute tolerance is at least the smallest normal number.

When a Maxwell electric update overflows an intermediate term, evolution retries with scaled current and wave terms, and rejects a non-finite resulting electric field. This recovers selected finite updates but does not guarantee preservation of every extreme cancellation.

Maxwell evolution and residual APIs reject non-finite output grids, including magnetic histories and scalar constraint residuals. Intermediate overflow can still prevent a representable final result.

Maxwell evolution rejects time configurations whose final electric timestamp overflows or whose first magnetic half-step rounds to zero; the residual APIs accept their independently supplied histories and timestep.

`MaxwellEquations.gridCoordinates({shape,origin,spacing})` returns conventional periodic Yee sample positions for interpreting the solver’s forward and backward differences. `electric[0..2]` and `magnetic[0..2]` each contain coordinate grids shaped `[Nx,Ny,Nz,3]`; the index selects the field component. Electric components occupy edges offset by one half-cell along their own axes, while magnetic components occupy faces offset by one half-cell along the other two axes. `charge` gives node positions for backward electric divergence and `magneticDivergence` gives cell-center positions for forward magnetic divergence. Origin defaults to zero and spacing to one; spatial dimensions must each be at least two and the grid remains limited to 32,768 cells. Positions can lie half a cell beyond the last node, representing locations on the periodic grid. These coordinates describe the discrete solver placement, not an interpolation of its fields.

`MaxwellEquations.collocateFields(E,Bbefore,Bafter)` averages one electric frame and the bracketing magnetic half-time frames to charge nodes at the electric time. It uses periodic spatial neighbors: two electric edge samples per component and four magnetic face samples per component, followed by the average of the two magnetic times. All three inputs must have the same `(...,Nx,Ny,Nz,3)` shape, with each spatial dimension at least two; matching leading batch dimensions are preserved. The per-grid cell limit and a one-million-scalar aggregate output limit apply. For `evolve` histories, use `E[n]`, `B[n-1]`, and `B[n]` for an interior electric frame `n`. This is linear interpolation and smooth-field accuracy is not guaranteed near discontinuities; floating-point underflow may still affect extreme values. The returned `{electric,magnetic}` arrays can be passed to `EMFieldTensor.fromEB` for node-aligned derived quantities.

A periodic vacuum plane-wave regression combines `evolve` and `collocateFields` at an interior time and observes near second-order magnetic-field convergence for 8, 16, and 32 samples per wavelength. This verifies that particular smooth case, not accuracy for every field or grid.

`MaxwellEquations.collocateHistory(Ehistory,BhalfHistory)` performs this interpolation for every interior electric frame, returning `{frameIndices,electric,magnetic}`. The indices identify the corresponding entries of the original electric history; use them to select the original electric timestamps. Histories must have matching `(frames,...,Nx,Ny,Nz,3)` shapes, with at least three electric frames and exactly one fewer magnetic half-frame. Output retains leading batch dimensions and is limited to one million scalar components. End electric frames have no two bracketing magnetic half-frames and are omitted.

`RetardedField.retardedTime` follows Lib4's coordinate-scaled coincidence rule: separations at or below `64·Number.EPSILON·max(1, |x|, |x_s|)` return the observation time. The potential rejects the same near-source scale using the observation-position norm, including the unit-scale floor. Bisection accuracy remains limited by the supplied tolerance and representable time spacing.

The Lib4 `RetardedField` data fields map to `sourceWorldline`, `sourceVelocity`, `charge`, `maxSpeed`, `c`, `epsilon0`, `maxIterations`, and `tolerance`. These JavaScript properties are mutable; constructor validation is not repeated on assignment, so callers must preserve valid callbacks, constants, bounds, and iteration settings when changing them.
